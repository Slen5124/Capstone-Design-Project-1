# LOSO 실험 규격 (protocol `loso-v1`)

이 문서와 `protocol.json`은 **실행 전에 고정**한다. 결과를 보고 값을 바꾸지 않는다. 값을 바꾸면 `protocol_version`을 올리고,
버전이 다른 결과는 섞지 않는다. 현장은 가명(SITE_A~D)으로만 쓴다.

## 1. 연구 질문

고정 카메라 사진으로 실내 마감(벽 보드, 천장) 설치율을 추정할 때, **처음 보는 현장**에서

1. 동결한 자기지도 인코더(DINOv2) 위에서 디코더 계열(경량 MLP / CNN식 UPerNet / ViT 전용 DPT)이 성능에 얼마나 기여하는가
2. 학습 없는 추론 단계 기법(TTA, 작은 ROI 확대, 가시성 인지 인과 단조 보정)이 얼마나 기여하는가

## 2. 고정 사항

| 항목 | 값 |
|---|---|
| 인코더 | `vit_base_patch14_reg4_dinov2.lvd142m` (DINOv2 ViT-B/14 + registers, Apache-2.0, 동결). Apache 계열 DINOv2 중 최신 |
| 사용 블록 | 2 / 5 / 8 / 11 (12블록의 1/4·1/2·3/4·끝) |
| 디코더 | `mlp` (SegFormer식, 약 1.05M), `upernet` (ViT 피라미드 어댑터 + UPerNet, 약 4.10M), `dpt` (약 4.50M), `linear` (하한선, 약 0.05M, 맨 마지막 실행) |
| 헤드 | 물체 8클래스(자동 라벨, 손실 가중치 0.5, 희귀 클래스 가중) + 상태 6클래스(벽 미설치/설치, 천장 미설치/설치, 가림, 대상 아님) |
| 초기화 | 인코더만 사전학습. 어댑터·디코더·헤드는 PyTorch 기본 초기화를 시드로 고정(`reset_trainable(seed)`) |
| 학습 | 1024×576, batch 4, AdamW (lr 1e-3, wd 1e-4), OneCycle (warm-up 10%), AMP, 15 epoch |
| 학습 데이터 | 사람 라벨 ×3, 전파 라벨 가중치 0.5, 약라벨 가중치 0.3 (sample id 순 3장에 1장). 약라벨 개수 제한 없음(`weak_cap_total: null`) — 학습 쪽 현장의 데이터를 모두 쓰는 LOSO 본래 설정. 그래서 fold마다 학습량이 다르다(SITE_A·C fold는 약라벨 현장이 둘) |
| 증강 | geo(0.5~1.0배 축소·이동·좌우반전, 확률 0.8), 색·밝기, copy-paste 0.5 — 예비 실험 E4와 동일 |
| 최종 모델 | **마지막 epoch** (val로 고르지 않음). val 기준 최적 epoch의 점수는 보조로만 보고 |
| 시드 | 0, 1, 2 (linear는 0만) |
| 실행 수 | 3 디코더 × 4 fold × 3 시드 = 36회 + linear 4회 |

## 3. 데이터 분할 (`folds.py`, 개인 전달 번들에 목록 고정)

- **test** = hold-out 현장의 사람 라벨 전부. SITE_A는 날짜마다 1장(시드 0). SITE_B·D는 사람이 라벨한 대상만 채점.
- **val** = 학습 쪽 SITE_A·SITE_C 사람 라벨. 첫 날짜부터 7일 블록으로 나누고, 5블록 중 1개 잔여류(시드 0)를 val로.
  val 날짜 ±1일의 사진은 학습에서 제외(인접 사진 누출 방지). SITE_B·D 사람 라벨은 val로 쓰지 않음(그 약라벨이 사람 라벨의 복사본이라서).
- **train** = val 사이트의 나머지 사람 라벨 + SITE_A 전파 라벨(val·버퍼 날짜 제외) + 학습 쪽 SITE_B·D 약라벨.
- hold-out 현장의 사진은 어떤 역할로도 학습에 들어가지 않는다.
- 같은 현장 test는 두지 않는다(모든 현장이 한 번씩 test가 된다).
- 제외 목록(라벨 오류 사진)과 예외 목록(보고 시 포함/제외 둘 다 계산)은 번들에 고정.
  예외: SITE_B W02 2025-08-18(보호막 덮인 기존 벽), SITE_D 철거 구간 날짜.

## 4. 추론 단계 (학습 없음)

| 단계 | 변형 |
|---|---|
| 추론 | `base`, `flip`(좌우반전 평균), `ms`(flip × 1.0/1.25/1.5배), `ms_roizoom`(ms + ROI가 사진의 3% 미만이면 25% 여유로 잘라 키워 재추론) |
| 시간축 | `raw`(날짜×벽 평균), `causal`(벽별 인과 등위회귀), `causal_view`(시점·벽별), `causal_view_w`(+보이는 비율×확신도 가중), `causal_view_w_reset`(+20%p 넘는 하락이 2일 연속이면 재시작·철거 의심 표시) |

- 인과 = 그날까지의 예측만 사용(실시간 가능). 보정값은 그날 예측보다 낮아지지 않는다.
- 모델별 추천 파이프라인(추론 × 시간축 조합)은 **val 벽 MAE로만** 고른다. test로 고르지 않는다.

## 5. 지표와 보고

- **주 지표**: 벽 설치율 MAE (hold-out 현장, 날짜×벽 행). 보조: 최대 오차, ±5/±10%p 이내 비율, install mIoU,
  완료 판정 F1(설치율 0.9 기준), ROI 크기 구간별 MAE(사진의 1% 미만 / 1~5% / 5% 이상, 사진 단위).
- **평균**: SITE_A·B·C를 같은 비중으로(macro), 시드별로 macro를 구한 뒤 평균 ± 표준편차.
  SITE_D는 철거 현장 사례로 따로. 천장은 SITE_B·C fold에서만.
- 예외 목록 **포함 / 제외 두 기준**을 모두 보고.
- 디코더 비교: 날짜×벽 행 짝지은 부트스트랩(B=10,000, 시드 0), fold별 + macro(fold 층화).
- 판정 보류(위험도-커버리지): 날짜×벽 행을 확신도(보이는 비율 × 예측 확신도) 순으로 정렬해, 자동 보고 비율 100~50%에서의 MAE.

## 6. 사전 예상 (실행 전 기록)

| 질문 | 예상 | 결과별 해석 |
|---|---|---|
| 디코더 차이 (macro 벽 MAE) | 세 디코더 차이가 시드 표준편차 안 | 차이 없음 → "동결 DINOv2에서 디코더는 부차적, 비용으로 선택" / DPT 우세 → "ViT 특징엔 ViT 전용 디코더" / UPerNet 우세 → "적은 라벨에선 전역 맥락(PPM)이 중요" |
| 작은 벽 (ROI 1% 미만) | DPT ≥ UPerNet ≥ MLP, linear 최하 | 모두 linear처럼 실패하면 병목은 토큰 해상도 → 고해상도 추론·ROI 확대 효과로 확인 |
| 추론 단계 | ms·roizoom이 작은 벽에서 개선, 전체 효과는 작음 | 효과 없음도 그대로 보고 |
| 시간축 | 시점별·가중 보정이 기존 인과보다 낫거나 같음. SITE_D에서는 reset이 필요 | reset이 오히려 나쁘면 한계로 보고 |
| 현장별 | SITE_A 쉬움(큰 벽), SITE_B 작은 벽에서 어려움, SITE_C 진척 후반만 있음 | 현장 특성 표로 설명 |

## 7. 재현성

- 난수: Python / NumPy / PyTorch(CPU·GPU) 고정, 셔플 순서는 (시드, epoch)로, 증강 난수는 (시드, epoch, 사진 번호)로 결정
  → 작업자 수와 이어서 실행 여부에 상관없이 같은 데이터 순서·증강.
- 엄격한 GPU 결정론(`cudnn.deterministic`, `use_deterministic_algorithms`)은 **쓰지 않는다**(2026-10-28 결정, 첫 실측 전).
  기준 노트북(RTX 4060 Laptop)에서 학습이 8배 느려졌다(step당 5.5초 → 끄면 0.67초, 실행 1회 26시간 → 약 3.2시간).
  `cudnn.benchmark=False`는 유지(실행마다 연산 방식이 바뀌지 않게).
- 따라서 GPU 결과는 같은 시드로 다시 돌려도 덧셈 순서 차이로 끝자리가 조금 다를 수 있다. 이 차이는 보고하는
  시드 간 편차(시드 3개, 평균 ± 표준편차)보다 작을 것으로 예상하며, 두 PC에서 같은 설정 1회(upernet / SITE_B / 시드 0)를
  돌려 `compare`로 실제 크기를 기록한다.
- 실행마다 `config.json`(설정·버전·GPU·코드 해시·git 커밋·인코더 가중치 해시·데이터 해시), `environment.txt`,
  `split_manifest.json`을 학습 전에 저장. 번들과 export는 `check`가 해시로 확인한다.
- 중간 저장은 `resume.pt` 하나를 매 epoch 덮어쓰고(가중치·옵티마이저·스케줄러·AMP·난수 상태), 끝나면 지운다.
  남기는 가중치는 `final.pt`(마지막 epoch) 하나.

## 8. 환경

Python 3.9, PyTorch 2.6.0 (+cu124), timm 1.0.30, NumPy 1.26.4 (`environment.yml`). GPU 8GB급(RTX 4060 Laptop에서 확인).
