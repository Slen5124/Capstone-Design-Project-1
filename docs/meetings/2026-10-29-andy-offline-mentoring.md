## 1. 회의 요약

팀은 OxBlue 현장 사진으로 학습한 비전 AI의 벽체 설치 상태 분석 결과와, 이를 공정표·사진 제출·관리자 검토·보고서·챗봇으로 연결하는 웹 프로토타입을 시연하였다. 논의의 중심은 기존 공사관리 서비스 전체를 재현하는 것이 아니라, **사진 기반의 관찰 가능한 공정 상태 분석**과 **근거를 갖춘 보고서 자동 생성**으로 현장의 반복 업무를 줄이는 데 두었다.

현재 비전 AI가 직접 분석하는 대상은 벽체 설치 상태를 우선으로 하며, 해당 관측값은 카메라 시야와 ROI 안의 설치/미설치 픽셀 비율이다. 따라서 이를 매장 전체의 공사 진행률이나 준공 승인으로 동일시하지 않는다. 바닥·천장·조명·집기·설비 등은 실제 사진 확보, 라벨 품질, 관측 가능성 및 별도 성능 검증을 전제로 하는 확장 후보로 정리하였다.

## 2. 비전 AI 개발 현황 및 성능 평가

### 2.1 데이터와 분석 범위

- OxBlue 카메라를 통해 미국 4개 도시의 공사 사진을 확보하여 다운로드, 전처리, 라벨링 및 학습을 진행하였다.
- 현장별로 카메라 시점이 바뀌거나, 대상이 가려지거나, 필요한 공정 단계의 사진이 촬영되지 않는 문제가 확인되었다. Las Vegas는 회의에서 약 47회의 구도 변경 사례로 언급되었고, Brea는 상대적으로 카메라 구도가 안정적인 현장으로 설명되었다.
- 동일한 공종을 여러 도시에서 공통으로 관찰할 수 있는 데이터가 제한적이므로, 현 단계에서는 벽체 설치 상태를 우선 대상으로 삼았다. 설치 완료 영역과 미설치 영역을 분할(segmentation)하여 오버레이와 설치 비율로 시각화하였다.
- 도시별 자료의 다운로드·정리·구도 분류·ROI 정의·정답 라벨 제작과 검수에는 수 주가 걸릴 수 있다. 특히 정답 데이터 제작 자체에 큰 시간이 들며, 일부 정답은 사진의 가림·거리·시점 때문에 불확실성을 가질 수 있음을 전제로 한다.

### 2.2 평가 방식과 해석

- 한 도시(현장)를 학습에서 제외하고, 나머지 도시(현장)로 학습한 뒤 제외한 도시에서 평가하는 현장 단위 평가 방식이 소개되었다. 이는 신규 현장으로의 일반화 가능성을 확인하기 위한 방식이다.
- 회의 중 벽 설치율 예측 오차가 약 **4.5~5.7%p** 수준으로 언급되었다. 이 값은 회의 발언에 근거한 범위이며, 회의 당시의 모델·분할·집계 조건을 별도로 확인해야 한다.
- 현재 저장소의 후속 공개 실험 문서에는 현장 단위 LOSO(`loso-v1`) 평가에서 DINOv2 + UPerNet의 벽 설치율 MAE가 평균 **5.44%p**(SITE_A~C macro), 벽 mIoU가 **63.6%**, 완료 기준 90%에서 F1 **0.92**로 기록되어 있다. 이 문서는 회의 중 언급한 약 4.5~5.7%p 범위와 대체로 부합하지만, 회의의 수치를 자동으로 동일 실험의 확정값으로 간주하지 않는다. 원 실행 결과와 평가 규격을 연결해 재확인해야 한다.
- IoU는 픽셀 단위 분할의 겹침 정도를, 설치율 MAE는 날짜×벽 단위 설치 비율의 평균 절대 차이를 나타낸다. 두 지표는 서로 다른 평가 대상이며, 어느 하나만으로 전체 시스템 성능을 판단하지 않는다.

### 2.3 측정상 제약과 운영 원칙

- 카메라 구도가 변하면 동일 ROI를 그대로 비교할 수 없으며, 대상 벽과 비교 영역을 다시 확인해야 한다. 카메라 위치, 원근, 가림, 조명 및 촬영 범위는 설치율 추정에 영향을 준다.
- 벽 설치율은 관찰 가능한 ROI 안에서 `설치 / (설치 + 미설치)`로 측정하는 지표다. 가림 또는 대상 아님 영역은 제외하며, 가시성 부족 시 계산 보류 또는 사람 검수가 필요하다.
- 따라서 벽 설치율은 실제 벽 면적, 매장 전체 공정 진행률, 공사 완료 승인과 동일한 수치가 아니다. 공정표의 작업 단위와 관측 근거를 연결한 뒤에도 전체 진행률 환산 규칙은 별도 합의가 필요하다.

## 3. 전체 시스템 파이프라인과 구현 범위

회의에서 제안·시연한 목표 흐름은 다음과 같다.

```text
간트 공정표 업로드 및 작업 구조화
  → 공정표 기반 작업 분류
  → 카메라 영상 또는 현장 제출 사진 수집
  → Vision AI의 관찰 가능한 작업 분석
  → 관찰이 어렵거나 증빙이 필요한 작업은 현장 담당자에게 제출 요청
  → 중앙 관리자의 승인·반려·추가 기간 요청 검토
  → 공정표와 관찰 결과를 함께 고려한 공정 상태 평가
  → 주간 보고서 자동 생성
  → 대시보드 및 프로젝트별 AI 챗봇 조회
```

| 구분 | 현재 저장소 문서상 구현 또는 시연 상태 | 회의에서 제안·추가 검토한 범위 |
| --- | --- | --- |
| 비전 | 벽 중심의 상태 분할, ROI별 설치율·근거 출력, 현장 단위 평가가 문서화되어 있음 | 천장·바닥·조명·집기·설비의 데이터 확보, 라벨링 및 별도 성능 검증 |
| 공정표·백엔드 | 공정표 원본·작업·선후 관계와 비전 결과를 저장·조회하기 위한 API/DB 구조가 문서화되어 있음 | 작업 분류와 관찰 결과를 실제 운영 데이터로 자동 연결하고 평가 규칙을 확정 |
| Frontend | 지도·매장·간트·검토·보고서·챗봇을 포함한 공개 프로토타입은 Mock Data와 브라우저 로컬 저장으로 시연 | 실제 백엔드, Vision AI, Agent 및 알림 흐름 연동 |
| Agent/LLM | Agent 호출·근거 조회·결과 저장은 후속 구현 범위로 명시됨 | RAG 기반 프로젝트 챗봇, 근거 기반 보고서 생성, 사용자 작업 지원 에이전트 |

## 4. 프론트엔드 및 대시보드 시연

시연 프로토타입에는 다음 업무 화면과 흐름이 포함되었다.

- 글로벌 매장 지도 기반의 프로젝트 조회 및 관리
- 신규 매장 등록과 매장별 현장 관리자 정보 설정
- 공정표 업로드 및 간트 차트 표시, 작업 상태별 색상 구분
- 작업 완료 확인 요청, 중앙 관리자의 승인·반려, 추가 기간 요청 및 검토 이력 관리
- 주간 보고서 조회·생성 화면과 프로젝트별 챗봇
- 모바일 기반의 현장 사진 제출 화면

시연 데이터와 일부 화면 동작은 Mock Data를 사용하였다. 따라서 지도·대시보드·간트 UI가 보였다는 사실만으로 실제 백엔드 저장, 비전 추론, 승인 워크플로, Agent 응답이 모두 연결되었다고 해석하지 않는다. 실제 API와 AI 시스템의 통합은 후속 개발과 E2E 검증이 필요하다.

## 6. 카메라 데이터 수집과 신규 현장 검증

### 6.1 데이터 수집 방식

- 기존 OxBlue 서비스는 미국 매장 공사 현장을 중심으로 활용되고 있다. 현장마다 설치 위치·촬영 각도·촬영 주기가 달라 분석 품질에 영향을 준다.
- 일반 IP 카메라를 **RTSP**로 연결해 OxBlue와 유사하게 영상을 수집하는 방안이 제안되었다. 회의 메모의 `RSTP`/`RSDP` 표기는 표준 프로토콜명 `RTSP (Real Time Streaming Protocol)`의 표기 오류로 정리한다.
- 네트워크 제약이 있는 환경에서는 중계 서버 등 연결 방식을 검토할 수 있다는 의견이 나왔다. 이는 기술 제안이며, 실제 네트워크 구성·보안·운영 책임을 포함한 도입 확정 사항은 아니다.
- 기존 OxBlue와 신규 IP 카메라의 화질, 시점, 압축, 조명 및 촬영 환경이 달라지면 도메인 차이가 발생할 수 있다. 신규 카메라 도입 시 별도의 검증·추가 학습 또는 라벨 보강이 필요할 수 있다.

### 6.2 신규 현장과 데이터 확보 후보

- Hong Kong, Macau, Australia 등 신규 현장을 실증·일반화 평가 후보로 논의하였다. 실증은 실제 카메라 또는 현장 사진을 적법하게 확보할 수 있는지를 전제로 한다.
- Hong Kong Lee Garden 공사는 팀원 메모에 종료 예정일이 **12월 11일**로 기록되어 있으나, 회의록에서는 확정 일정이 아닌 **확인 필요 정보**로 관리한다.
- Macau 공사 자료와 Australia 현장 데이터의 활용 가능성을 확인한다.
- Torrance 데이터는 바닥·천장 분석에 활용할 수 있는지 검토한다. 데이터가 있다고 해서 해당 공종의 분석 모델 성능이 검증된 것은 아니다.
- 신규 현장 사진을 확보하면 기존 학습 현장과 분리하여 일반화 성능, 카메라 종류, 촬영 환경 차이를 평가한다.

| Photos | 현장 사진 업로드 및 조회 |
| Scheduling | 기능은 제공되지만 실제 일정 관리는 별도 도구를 사용하는 경우가 있다는 설명 |

피드백의 핵심은 기존 제품의 모든 기능을 복제하는 것이 아니라, 사용 빈도가 높고 분산되어 있는 핵심 업무를 연결하는 것이다. 특히 사진 관찰, 증빙 제출·검토, 공정표 연계, 보고서 자동 생성의 통합이 제품 차별점이 되어야 한다.

## 8. 실제 현장 관리 요구사항

Andy 멘토가 현장 방문 시 중점적으로 확인하는 단계는 다음과 같다.

- 철거 이후 레이아웃과 사이트 마킹
- 기둥, 벽체, 도면 치수의 일치 여부
- 금속 스터드(metal stud) 설치
- 벽체 내부 전기·설비 상태
- 석고보드 마감 이전의 검토
- 가구·집기 설치 전후 확인
- 마감 결함과 Punch List 확인

이는 현재 AI가 자동 판정할 수 있다고 확정한 공종 목록이 아니다. 현장 업무를 이해하고 데이터·증빙·검토 기능의 요구사항을 도출하기 위한 조사 결과로 취급한다. 자동화 대상 확대는 각 공종별 사진 가시성, 라벨 기준, 정답 데이터, 성능 검증 및 관리자 검토 절차를 갖춘 뒤 판단한다.

## 9. LLM, RAG 및 서버 논의

- 로컬 또는 자체 호스팅 LLM 사용을 검토하며, Qwen 계열 모델이 후보로 언급되었다.
- 학교 GPU 서버의 H100 활용 가능성과 기존 A6000 등 GPU 자원의 역할 분담을 검토한다.
- Alo Yoga 관련 문서, 공정표, 비전 관찰 결과, 관리자 검토 이력 및 보고서 데이터를 RAG(Retrieval-Augmented Generation)로 연결하여 프로젝트 범위에 맞는 근거 기반 답변을 제공하는 방향을 논의하였다.
- RAG는 저장·검색된 관련 근거를 응답 시 참조하는 방식이며, 모델 가중치를 학습하거나 파인튜닝하는 것과 동일한 개념이 아니다. 파인튜닝은 필요 시 별도로 검토할 개선 방향이다.
- 보고서 자동 생성과 프로젝트 전용 챗봇을 우선 활용 사례로 두고, 장기적으로는 사용자의 제출 요청·검토·조회 작업을 돕는 에이전트 기능도 검토한다.
- 팀원 메모의 `Qwen 17B`와 회의 발언에서의 `70B` 관련 표현은 서로 일치하지 않는다. 실제 서버에 설치·운영할 모델명, 파라미터 규모, GPU 요구량과 접근 방식은 확인 후 기록한다.

## 10. 보안 및 운영 환경

- AWS 기반 웹 서비스와 학교 GPU 서버에서의 LLM 실행을 분리하는 운영 방향을 논의하였다.
- 특정 포트 개방, IP 기반 접근 제어, MAC 주소 기반 접근 제어 제안이 언급되었고, 계정·권한 관리와 현장 담당자별 사진 제출 권한도 필요 사항으로 정리되었다.
- 내부 공정표, 현장 사진 및 검토 이력이 외부에 노출되지 않도록 해야 한다.
- MAC 주소 기반 원격 접근 통제는 회의 중 제안된 한 가지 방법일 뿐, 충분한 보안 수단으로 확정하지 않는다. 실제 배포 전에는 인증·인가, 전송·저장 암호화, 비밀 관리, 네트워크 분리·방화벽, 감사 로그, 권한 회수 및 취약점 대응을 포함한 별도 보안 검토가 필요하다.

## 11. 멘토 및 지도교수 피드백

- 기능을 과도하게 넓히지 말고, 실제 사용 빈도가 높은 핵심 기능에 집중한다.
- 대시보드 화면 자체보다 AI 자동화가 만드는 업무 효율 개선을 차별점으로 제시한다.
- 기존 서비스와 단순히 유사한 기능을 만드는 것보다, 사진 기반 공정 관찰과 보고서 자동 생성의 실질적 가치를 보여주는 것이 중요하다.
- 신규 현장·카메라 데이터에서 성능을 검증하여 실제 적용 가능성을 확인한다.
- 챗봇은 프로젝트 관련 질문에 대해 근거를 제시할 수 있어야 하며, 장기적으로는 사용자 작업을 지원하는 기능도 검토한다.
- 학생팀의 개발 기간과 구현 역량을 고려해 통합 범위와 기능 우선순위를 조정한다.
- 연구·논문에서 회사명 또는 내부 데이터를 활용하는 경우, 공개 범위와 사전 협의 절차를 준수한다.

## 12. 최종 합의 및 개발 우선순위

아래 우선순위는 회의 논의를 바탕으로 한 개발 방향 정리이며, 세부 일정·담당·완료 기준이 공식 확정되었다는 뜻은 아니다.

1. **기존 Vision AI 결과의 실제 시스템 연결**
   카메라 사진을 분석해 관찰 가능한 공정 상태를 산출하고, ROI·원본 사진·오버레이 등 근거와 함께 제공한다.
2. **자동 보고서 생성**
   공정표, 사진, Vision 관찰 결과, 관리자 검토 정보를 연결해 근거 기반 보고서를 자동 생성한다.
3. **통합 대시보드 및 LLM 챗봇**
   관리자가 여러 시스템을 오가지 않고 핵심 정보를 확인하며, 프로젝트 관련 질문에 근거 있는 답변을 받을 수 있게 한다.
