사진의 개수가 절대적으로 부족

매 과정에서 매장 전체의 사진을 보내거나
사진을 보내는 단계에서 어느정도 공정의 진행 단계를 정해두고 넘어가야 할 듯.

그것이 아니라면)
정해진 위치에서 정해진 방향으로 촬영하여 진행률을 유추하는 방법 밖에 없음.

매장의 구조와 구성에 따라 달라지는 촬영 위치는 고려해야함.
인테리어 구조물에 의해 시야 차단이 있는 편, 계산하는데 고려해야함.


아스트라 나오면서 카메라 사진을 보고 360도 3D 이미지 구현 기능이 있다.
360도 카메라를 현장에 두고 촬영하여 3D모델링에 엎어씌워 현장을 3D화 시킨다.


그럼 2D로도 되지 않을까?

포인트 클라우드 기법 << 이미지로 3D를 옮기는 방법이 있다.
다만 이건 이미지의 시각화 뿐이기에 %계산은 직접 해야한다.

자재나 가림막에 가려지는 부분은 에이전트 단에서 계산이 불가능한 이유를 첨부해주었으면 한다.
ex) 자재로 가려져 확인이 불가능하다.
ex) 책상이 놓여있는 것으로 보아 바닥은 완공이 되었을 것으로 유추된다.

에이전트AI 단에서 처리할 데이터는 무엇인가?
뭐라 했었지.

비전AI 단에서 나오는 결과물은?
특정 공정 구역의 진행률이 n%이다

학습에는 에이전트가 개입하지 않음.
비전 AI단에서 나온 결과를 에이전트 단에서 처리하면 됨.

이미지나 비디오가 들어오면
공정률이 얼마인지 결과가 나온다.

공정 진행률을 받고, 공정표와 비교해서 진행률의 정도 비교를 진행.
이 때 이미지나 비디오를 보고 해당 공정 지연의 원인을 확인, 혹은 파악이 어려울 경우 사유를 출력


계단의 경우 선형적으로 올라가지 않음.
2~3주차는 진행속도가 더욱 빨라짐.
단순히 범위, 철근 10개 중에 3개니까 30%로 계산하면 안될 것 같다.

로컬 LLM이라고 하는 부분에서, 비전단이 정답평가를 했을 때 n% 결과가 나오는 경우, 아웃라이어(예외 경우)가 나오는 경우가 있을 것이다.

탐지를 했을 때 가려져 보이지 않는 경우가 있다면, 이전 관측값보다 값이 떨어지거나 튀는 데이터가 있을 것이다.
그 때, LLM이 사진을 함께 보며 판단하는 기조로 생각을 했다.

비전에서 예외케이스가 발생했을 때, 재계산을 하거나 사유를 말해줄 줄 알았다.
그럼 에이전트도 학습을 시켜야하나?

로컬 LLM이 성능 구린 GPT다.
학습을 안시켜도 나오긴 할거다.
정교화 시키는 것이 역할.

로컬 LLM이 가중치를 건들지는 못하지만, 여럿의 전문가 LLM을 만들고 투표를 하는 방식으로 정교화가 가능할 것이다.

지금 사진은 현장책임자가 아니라 회사측 사람이 찍은 것 같다.
현장책임자에게 문서처럼 위치와 방향을 정해 사진을 찍게 하거나, 위치를 정해 카메라를 설치하는 방법이 있을 것.


데이터 전처리에 대해.
사용 LLM을 사용하여서라도 데이터를 크롭하여 input data로 쓸 수 있는 데이터로 바꾸어야함.
그 데이터에 대한 라벨링이 필요함.

현재 문제는 제공받은 자료에 준공률이 적혀있지 않다.

데이터셋을 새로 찾는 방법도 있음.
