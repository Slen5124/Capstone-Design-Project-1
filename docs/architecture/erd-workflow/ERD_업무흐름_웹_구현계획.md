# ERD 업무 흐름 웹 구현 계획

[실행 HTML](ALOHA_ERD_업무흐름.html)

## 화면과 동작

1. 왼쪽에 전체 ERD와 12개 업무를 둔다. 업무를 선택하면 입력, 서버 처리·조회, 저장, 출력 네 단계가 바뀐다.
2. 중앙 ERD의 테이블을 조회는 파랑, 저장은 초록, 양쪽은 보라로 표시한다. 관련 없는 테이블은 흐리게 처리한다.
3. 테이블을 선택하면 관계선을 강조하고 하단에 전체 필드, PK/FK, 추가 여부, 사용처를 표시한다.
4. 확대·축소와 화면 맞춤으로 전체 구조와 세부 내용을 오간다. 작은 화면은 메뉴를 가로로 보여준다.
5. 화면 안의 구현 계획에서 실제 백엔드 연결 순서를 확인한다.

## 구성

현재 산출물은 외부 라이브러리·CDN 없이 여는 단일 HTML이다. 데이터는 문서에 포함한 테이블·관계·업무 정의를 사용한다. 업무 선택 상태와 테이블 선택 상태만 브라우저 메모리에 두고, 업무 선택은 서버 쓰기를 발생시키지 않는다.

향후 유지보수 시 테이블·관계와 업무 정의를 별도 JSON으로 분리할 수 있다. 각 업무는 입력/처리/조회 테이블/저장 테이블/출력/권한 규칙의 같은 형식을 사용한다. 운영 데이터의 행·사진·대화 내용은 이 설계 도구에 넣지 않는다.

## 실제 연결 단계

1. 사용자 인증과 현장 권한, 필요한 컬럼만 반환하는 현장·간트 API를 연결한다.
2. 업로드·현장 증빙·본사 검토·요청 대화와 결정 API를 연결한다. 결정 상태와 이력은 같은 트랜잭션에 저장한다.
3. 대표 사진 수집과 Vision 추론, 작업별 관측 연결을 붙인다.
4. 주간 보고서·챗봇의 근거 조회와 생성 결과 저장을 연결한다.
5. 005 통합과 기존 workflow 호환은 복원 DB에서 검증하고 운영 적용했다. 정규 업무 API를 연결할 때 사용자 인증·RLS·컬럼 권한과 권한 경계를 추가 검증한다.

## 확인 기준

- 20개 테이블을 모두 표시하고 각 관계의 부모·자식이 존재한다.
- 12개 업무가 참조하는 테이블 ID가 실제 설계와 일치한다.
- 업무 선택 시 네 단계와 테이블 색이 함께 바뀐다.
- 테이블 선택 시 해당 필드와 FK 관계가 표시된다.
- 확대·축소, 키보드 버튼 조작, 작은 화면 탐색이 가능하다.

005 통합을 운영에 적용하고 실제 20개 테이블·186개 필드·외래 키를 HTML에 반영했다. 기존 workflow 호환 API는 검증했다. 사용자별 권한 정책과 정규 업무 API의 추가 연결은 후속 작업이다.
