# 업로드 전 보안 검사

2026년 11월 9일 20개 테이블 통합 SQL·호환 코드·문서와 실제 스키마 정의를 대상으로 검사했다.

- Gitleaks 8.30.1 공식 배포본의 SHA-256 체크섬을 확인했다. 파일 검사와 커밋 예정 diff 검사를 비밀값 가림 모드로 수행해 유출 패턴 0건을 확인했다.
- 개인키·환경 파일·백업·운영 데이터의 파일명 및 형식을 별도로 검사했다. 서버 주소, 접속 문자열, 개인 PC 경로·이메일과 비공개 조회 원본을 제외했다.
- schema.json과 새 설치 SQL은 구조만 포함한다. 데이터 덤프·실제 사진·파일 내용·서버 인증 설정과 백업은 포함하지 않았다.
- HTML의 외부 스크립트·스타일·폼과 내부 문서 링크를 검사했다. 실제 DB에서 20개 테이블·186개 필드를 확인하고 ERD의 실제 외래 키를 대조했다.
- 복원 DB에서 기존 자료 및 workflow JSON의 내용 보존, 매장 간 첨부 제약, 본사 검토 권한, 반려 사유, 중복 결정·적용 거부, 추가 기간 요청의 등록·승인·적용·재시도와 호환 뷰 7개를 확인했다.
- 새 빈 DB에서도 공개한 020 설치 SQL과 SQL 회귀 검사를 통과했다. 운영 전환 후 health·인증된 프로젝트/주간 자료/기간 요청 조회 및 서비스 재개를 확인했다.

## 매번 업로드하기 전

리뷰한 파일만 git add로 지정한 뒤 다음 명령이 성공해야 커밋한다. Gitleaks가 없거나 검사에 실패하면 중단한다. GITLEAKS_BIN으로 검증된 실행 파일 경로를 지정할 수 있다.

```sh
python tools/check_publication_security.py
```

현재 저장소는 공개 상태다. 이번 검사는 변경 파일과 커밋 예정 diff에 한정한다. 저장소 전체 이력의 보안 감사와 외부 침투 테스트는 별도다. 기존 내부 서비스 계정의 접근을 유지했으며 최종 사용자별 RLS·컬럼 제한과 인증 컨텍스트 연결은 추가 구현·검증 단계다.
