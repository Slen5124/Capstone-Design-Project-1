# 연동 검증 인수인계

FE는 공통 API 클라이언트로 요청하고 BE가 매장 권한과 자료를 확인한 뒤 DB·파일 저장소에 접근한다. 보고서 Agent와 Vision 결과는 BE 계약을 통해 연결한다.

## 이번에 반영한 내용

- FE 클라이언트의 시간 제한을 JSON·파일 본문 수신 완료까지 적용한다. 서버가 반환한 구조형 준비 상태와 오류 메시지를 표시한다.
- 주간 보고서 목록은 같은 주 자료의 현재 해시를 한 번만 계산해 각 저장 보고서의 변경 여부와 비교한다.
- 위 변경에 대해 오류 메시지, 지연된 본문, 같은 주 복수 보고서의 검증 중복을 테스트한다.

별도 팀 공유본에서 검토한 포털 조기 거절 시 요청 본문 로그 노출 문제와 PDF 레이아웃 fixture 보완은 이 저장소와 코드 구조가 달라 이번 커밋에 포함하지 않았다. 실제 서비스 이식과 검증이 필요하다.

## 검증 경계

변경된 FE API 클라이언트와 백엔드 API는 로컬 자동 테스트로 확인했다. 실제 PostgreSQL 잠금·동시성·RLS, 운영 배포, 실기기, 외부 Vision·GPU 연결은 이 변경에서 확인하지 않았다. DB와 파일의 백업·복구 및 매장별 접근 권한을 검증한 후 시험 환경에서 통합한다.

현재 저장소는 공개 범위를 기준으로 다룬다. 실제 현장 사진, 비밀번호, 접속 정보, 토큰, DB 덤프 및 개인 PC 설정은 커밋하지 않는다.
