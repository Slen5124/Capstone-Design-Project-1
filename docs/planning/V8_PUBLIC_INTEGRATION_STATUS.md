# v8 공개 코드 반영 범위

## 기존 반영

다음 커밋은 최신 main에 유지되어 중복 커밋하지 않습니다.

| 커밋 | 기능 | 확인 방법 |
| --- | --- | --- |
| b4b93ab | 선택 활성화 주간 보고서 입력·PDF 워커 | 기존 API 및 합성 DB의 PDF 생성 검사 |
| ee5e0e8 | Qwen 질문 처리·기록·후속 질문 | 모의 Qwen 응답으로 권한·기록·문맥 검사 |
| 3a15895 | 별도 보고서·챗봇 FE 연결 | API 클라이언트와 브라우저 모의 응답 검사 |
| e765bf7 | 설정·실행 문서 | 기능별 환경 변수와 실행 명령 검토 |

팀원이 이후 올린 기존 API 개선, FE 시간 제한·준비 상태 처리와 `final_model` 코드를 최신 main에서 받은 후 검사합니다. 기존 경로를 v8 파일로 교체하지 않습니다.

## 추가 반영

`src/llm_agent_module/vision_delivery/`의 검증기·업로더와 합성 테스트를 추가합니다. 실제 매장명과 시험 날짜, 자료 파일 의존성은 가상 값과 테스트 내부에서 만든 JSON으로 바꿉니다. 사진, 일정 원본, ZIP, PDF 생성물, 비밀 설정은 추가하지 않습니다. 실행법과 계약 차이는 해당 폴더의 README에 있습니다.

## 검증 구분

- 로컬 검사는 임시 SQLite, 합성 이미지·결과, 모의 HTTP 또는 모의 Qwen을 사용합니다.
- 앞서 AWS 별도 검증 환경에서 기존 배포 커밋으로 PDF 생성과 실제 Qwen 후속 질문을 확인했습니다. 그 환경의 업무 데이터는 별도로 복사한 SQLite와 저장소를 사용했습니다. 이것은 실제 PostgreSQL의 잠금·RLS·동시성 검증을 의미하지 않습니다.
- 이번 Vision 추가분으로 실제 모델 추론, 운영 업로드 또는 PostgreSQL 연동을 수행하지 않았습니다. 학교 GPU의 실제 Vision 추론부터 공개 API·보고서까지 전체 연결은 미검증입니다.
- 최신 팀원 변경까지 포함한 운영 배포, 접근 권한·백업 복원·실기기 검증은 별도 작업입니다.

## 제외

학교 GPU와 AWS의 주소·계정·키·토큰·비밀번호, DB 연결 설정, 개인 PC 경로, 대화 내역·운영 로그·덤프, 실제 브랜드·현장 사진·공정표·기존 시험 식별자를 제외합니다. 공개 테스트의 UUID와 날짜는 실행용 합성 fixture입니다.

기존 v8의 매장별 아카이브 색인과 특정 현장의 과거 라벨 보충 분기는 공개 코드에서 제외했습니다. 필요한 승인 자료는 서버 측에서 등록합니다. 기존 공개 데모의 검토된 자산과 팀원의 비전 모델 소스는 유지합니다.

## 이번 추가분 검사 결과

- Vision 검증·업로드, 기존 프로젝트 API, 주간 보고서 워커 및 챗봇·기록 모듈의 로컬 Python 검사 102개 통과.
- FE의 기존 API, 프로젝트 도구, Qwen 대화 및 AWS 화면 데이터 모델 검사 4개 통과.
- 새 Vision 테스트는 가상 매장, 가상 일정과 고정 합성 UUID를 사용합니다. 사진과 실제 JSON 파일은 테스트 입력으로 가져오지 않습니다.
- 반영 기준은 최신 main의 `1a4e0eb`입니다. 기존 BE·FE·모델 코드를 보존하고 Vision 전달 모듈·테스트·문서만 추가합니다.
- 커밋 전 저장소의 Gitleaks 검사와 별도 개인정보·운영 경로·파일 유형 검사로 공개 범위를 확인합니다. API 토큰은 환경 변수로만 받습니다.
