# 2번 시스템 구조도·3번 일정 분석

작성일: 2026-09-28 · 갱신일: 2026-10-11 · 이미지 분석 및 최신 팀 기준 반영

최신 개발 계획은 [현재 비전 파이프라인](current-vision-pipeline.md)에 정리했다. 구조 설명에는 최신 팀 기준을 함께 반영했고, 일정 표에는 당시 첨부 이미지의 작업명과 담당 표기를 보존했다.

프로젝트 경위: 기존 알로요가 매장 동선 분석 이후 A안(현장 사진 기반 공사 진행 모니터링)과 B안(개략 공사비·업체 견적)을 검토했고, 2026년 9월 19일 팀 내부 회의에서 A안을 우선 선택했다. 당시에는 필요 자료를 제공받기 어려우면 B안 전환도 검토했으며, 현재 사용자 확인에 따라 A안은 확정 과제다. 분석 대상 공종·구역, 상태 클래스 정의와 측정 산식은 미정이다. 근거와 PDF 요약은 [과제 변경 경위](project-background.md)에 정리했다.

## 1. 자료의 핵심 의도

2번은 현장 사진을 분할 모델로 분석하고 결과를 공정표와 비교한 뒤, 근거를 붙인 보고서·질의응답으로 제공하는 전체 구조다. 3번은 이를 비전 중심 작업과 백엔드·AI 에이전트 작업으로 나눈 일정이다.

설계의 장점은 학습과 운영 추론이 분리되어 있고, AI 에이전트 이전에 백엔드가 정형 결과를 저장·조회하며, 응답 생성 이후에도 수치·날짜·근거를 검증하도록 배치했다는 점이다. 구현의 핵심은 개별 모델 수보다 **사진 → 측정값 → 공정 비교 → 검증된 설명**이 하나의 근거 체계로 연결되는 데 있다.

## 2. 2번 구조도와 최신 팀 기준

| 영역 | 자료 및 최신 팀 설명의 구성 | 역할 해석 |
| --- | --- | --- |
| 데이터 저장소 | 사진·파일·DB의 공통 저장 계층 | 학습 사진, 신규 현장 사진, 대상·작업 정보를 연결 |
| 전처리·라벨 제작 | Grounding DINO + SAM 2.1과 비교 후 SAM3 채택 | SAM3 초안 → 사람 검수·상태 GT 확정 → 원본 사진과 함께 학습에 사용 |
| 모델 학습·평가 | ResNet-50 구성의 DeepLabv3+, U-Net, Mask R-CNN | 세 모델의 성능 비교 자체가 프로젝트 범위이며, 비교 후 운영 모델 선택 |
| 성능 개선 실험 | CLIP 지식 증류, VLM 라벨 검수 | 각각 학습 보조와 라벨 검수 보조 |
| 추론 입력 | 실제 사진 → 학습된 선택 모델; 분석 영역은 초기 사람 확인 | 학습을 마친 DeepLabv3+·U-Net·Mask R-CNN 중 선택 모델로 대상·상태 처리 |
| 추론 출력 | 상태별 클래스 결과·마스크, 후속 측정값 | 클래스명, 분석 대상과 계산 기준은 미정 |
| 전후 사진 매칭 | LoMa-L 또는 RoMa v2의 대응 관계 → 별도 기하 변환·정합 검증 | 같은 대상의 공통 영역이 검증된 경우에 상태 마스크 비교 |
| 결과 전달 | 자체 후처리 코드가 생성한 결과 JSON·근거 파일 참조 | 분할·매칭 출력과 검증 상태를 백엔드와 에이전트에 연결 |
| 서버·백엔드 | FastAPI, PostgreSQL; 추론 결과 JSON 수신·검증, 결과·공정표 저장·조회 | 처리된 실제 사진의 분석 결과와 근거를 축적 |
| AI 에이전트 | LangChain; 로컬 LLM 후보 Llama 3 / EXAONE | 서버에 저장한 분석 결과·공정표·문서 근거로 보고서·답변 생성 |
| 문서 검색 | ChromaDB, bge-m3 임베딩 | 문서 근거 검색 및 RAG |
| 최종 검증 | 수치·날짜·근거 대조; 불일치·근거 부족 시 검토 요청 | 검증을 통과한 보고서·질의응답 제공 |

전후 사진 매칭 후보는 LoMa-L과 RoMa v2다. 실제 선정은 비교·검증 후 결정한다.

라벨 제작 비교에서는 SAM3를 선택했다. 핵심 상태 인식 모델은 검수한 GT로 ResNet-50 기반 세 후보를 학습·비교한 뒤 별도로 선택한다. 전후 비교가 필요한 경우 매칭·정합 검증을 추가하고, 추론 결과는 JSON으로 서버에 전달해 Agent 보고서 작성에 활용한다.

## 3. 구현 전에 정해야 할 측정 기준

### 분석 대상·상태 클래스·측정 기준 (미정)

분석 대상 공종과 구역, 클래스 목록·정의, 측정 산식은 아직 정하지 않았다. 상태는 별도 클래스로 분리해 표현할 계획이다. 우선 클래스 결과와 마스크, 라벨 정의 버전을 보존하고, 기준이 정해진 후에 측정값을 계산한다.

측정 규칙에는 측정 단위, 포함·제외 영역, 분모가 없는 경우의 처리, 판정 불가 사유, 전후 비교의 공통 영역 기준을 명시한다. 클래스 픽셀 비율을 실제 물량이나 전체 공정률로 해석하려면 별도 환산 규칙이 필요하다. 구체적 클래스명·산식·수치 예시는 확정 후 추가한다.

### 분석 단위와 품질 기준

| 미정 항목 | 합의해야 할 내용 | 미정일 때 생기는 문제 |
| --- | --- | --- |
| 분석 단위 | 현장·구역·작업·촬영 시점·ROI 식별자 | 다른 위치나 공종의 결과가 섞임 |
| 상태 클래스 | 별도 클래스로 분리할 상태의 이름·경계·제외 기준 | 라벨 초안과 정답의 의미가 어긋남 |
| 촬영 조건 | 허용 시점·각도·해상도와 재촬영 조건 | 사진 차이를 시공 변화로 오인 |
| 품질 판정 | 가림·흐림·영역 부족·낮은 신뢰도 기준 | 측정 불가능한 사진도 숫자로 반환 |
| 공정표 연결 | 작업 ID, 계획 기준일, 버전, 산식·가중치 | 같은 관측값으로 상충하는 지연 판단 |
| 검토 흐름 | 검토 담당, 수정 이력, 승인된 결과 사용 규칙 | 경고만 남고 실제 처리 흐름은 끊김 |

분할 모델 후보는 픽셀 분할과 객체별 인스턴스 분할로 출력 단위가 다르므로 공통 비교 기준이 필요하다. 같은 테스트셋에서 클래스별 IoU·Dice와 추론 시간·메모리 등을 비교하는 방향을 제안하며, 측정 오차는 산식이 정해진 후 검토한다. 평가 지표와 합격 수치는 아직 확정하지 않았다. 세 모델을 비교하고 운영 모델을 선택하는 과정은 프로젝트 범위에 포함한다.

연속 촬영 사진이나 같은 현장의 유사 사진이 학습·평가 양쪽에 섞이지 않도록 현장·촬영 세션 단위 분리를 검토한다. CLIP 증류와 VLM 검수는 기준 모델 대비 개선을 확인하는 별도 실험으로 둔다.

## 4. 시스템 연결의 보완점

1. **공통 결과 규격:** JSON에 스키마 버전, 분석 ID, 현장·작업·사진 ID, 촬영 시각, ROI·모델 버전, 비율 산식, 품질 상태, 근거 참조를 포함한다. 수치만 전달하면 재현과 추적이 어렵다.
2. **저장 책임:** 원본·마스크·근거 이미지는 파일 저장 계층에, 메타데이터·측정값·공정표 버전은 DB에 두는 구성을 제안한다. 그림만으로 실제 저장 방식은 확정되지 않는다.
3. **비동기 처리:** 추론 시간이 길다면 접수·실행·완료·실패 상태와 재시도 규칙을 둔다. 동일 분석 ID의 중복 수신 정책도 정의한다.
4. **정형 수치와 문서 근거:** 비율·날짜·공정 차이는 백엔드에서 계산하고, RAG는 기준 설명·절차·문서 인용을 제공한다. LLM이 보고서 숫자를 새로 계산하거나 임의로 보충하지 않도록 한다.
5. **검증의 구체화:** 응답의 각 수치·날짜·판단에 분석 ID 또는 문서의 페이지·절 식별자를 연결한다. 근거가 없거나 불일치하면 자동 보고서 확정 대신 검토 대상으로 반환한다.
6. **전후 비교:** 같은 작업과 비교 가능한 ROI가 확인되고 정합 품질을 통과한 경우에만 변화량을 제공한다. 실패 시 단일 시점 결과와 비교 불가 사유를 반환한다.

## 6. 2번과 3번의 정합성 및 일정 위험

| 관찰 | 영향 | 보완 제안 |
| --- | --- | --- |
| 구조도는 Mask R-CNN, 당시 일정은 Faster R-CNN | 과거 표기를 현재 후보로 오인할 수 있음 | 현재 비교 후보는 Mask R-CNN이며, 일정표 갱신 시 이름 통일 |
| 구조도는 DeepLabv3+, 당시 일정은 DeepLab V3 표기 | 서로 다른 실험 설정을 비교할 수 있음 | 현재 후보는 DeepLabv3+이며, 구현·버전·ResNet-50 설정을 실험 기록에 고정 |
| 초기 JSON 계약 작업이 명시되지 않음 | API와 추론 결과를 마지막에 재작성할 위험 | 10월 초에 합성 JSON으로 최초 통합 |
| 사람 라벨 검수의 일정·완료 기준이 분리되지 않음 | 모델 실험 시작이 지연될 수 있음 | 라벨 가이드·검수 표본·데이터셋 버전을 선행 산출물로 지정 |
| 구조도의 전후 비교와 CLIP/VLM 실험이 일정에 명확히 대응되지 않음 | 핵심 기능과 선택 실험이 경쟁 | 단일 시점 MVP 이후 선택 과제로 배치 |
| 논문 구현이 후반에 큰 블록으로 배치됨 | 모델·인터페이스 변경이 통합 일정과 충돌 | 대상 논문·검증 가설·종료 조건을 먼저 명시 |
| E2E가 후반에 집중됨 | 실패·검토 요청·수치 검증 문제를 늦게 발견 | 초기 가짜 데이터 E2E, 중간 실모델 연동, 최종 회귀 검증으로 분리 |

‘논문 구현’은 당시 일정표의 작업명이다. 현재 세 모델 비교는 프로젝트 범위로 확정됐으나, 이를 논문 내용으로 사용할지와 논문의 구체적 연구 주제는 미정이다.

## 7. 제안하는 단계별 통과 기준

정확한 날짜는 재합의하되 기존 9~11월 흐름 안에서 아래 순서를 권장한다.

| 단계 | 목표 | 통과 기준 |
| --- | --- | --- |

## 8. 팀이 확인할 결정 사항

- 분석 대상 공종·현장·구역과 확보 가능한 데이터
- 상태별 클래스 정의, 포함·제외 영역, 측정 단위·산식과 실제 공정률 환산 여부
- 공정표의 입력 형식·버전·작업 ID와 일정 지연 판정 기준
- 모델의 구현 라이브러리·체크포인트·출력 헤드, 공통 비교 지표와 논문 연구 주제
- 정확한 날짜·완료 상태, 실행 장비와 처리시간 목표

A안, 공식 과제명·팀명과 담당 역할은 확정됐다. 최신 역할은 이윤한(모델 학습·추론·학습 테스트), 강태웅(전처리), 강원준(Agent·RAG), 김병조(DB·백엔드)이며, 위 일정의 담당 표기는 당시 기록으로 읽는다.

이 결정이 나오기 전에도 합성 데이터 기반 스키마, API 예제, 검증 사례와 문서 틀은 준비할 수 있다.
