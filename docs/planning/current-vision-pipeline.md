# 현재 A안 비전 파이프라인

갱신일: 2026-11-02. 기본 모델: **동결 DINOv2 ViT-B/14 (registers) + UPerNet**. 서비스 추론: **기본 추론 + 확신도 기반 사람 검수**.

## 1. 전처리와 학습

```text
현장 RGB 사진 + 기존 라벨 초안 / 사람이 작성한 라벨
 → 구도 구분 · 대상 ID · ROI · 가시성 · 시공 상태 검수
 → 이미지 + semantic / target / visibility / state 마스크 export
 → 현장·시간 기준 학습/검증/시험 데이터 분리
 → 동결 DINOv2 특징 → 학습 가능한 특징 피라미드 → UPerNet
 → semantic head 8클래스 + state head
```

라벨 생성 모델은 이 저장소의 실행 경로에 포함하지 않는다. 이미 보유한 라벨은 생성 출처를 로컬에 보존하고 사람이 검수한 뒤 사용한다. 자동 초안이나 전파 라벨은 사람 정답과 구분한다.

모델 입력은 RGB 사진이다. 대상 ID·ROI는 검수·측정·추적 메타데이터이며 RGB 입력에 자동으로 추가되는 채널이 아니다.
`--activity all`을 사용하면 상태 출력은 벽 미설치/설치, 천장 미설치/설치, 가림, 대상 아님의 6클래스다.
기본 단일 작업 모드는 4클래스이므로 기존 데이터와 체크포인트의 클래스 설정을 확인한다.

## 2. 추론과 측정

```text
새 RGB 사진 → 학습한 DINOv2 + UPerNet → 픽셀별 대상·상태 마스크
 → 구도별 고정 ROI / 대상 ID와 결합 → 관측 가능한 영역의 설치 비율 + 확신도
 → 확신도가 높은 날짜×벽은 자동 보고, 낮은 항목은 사람 검수로 보냄
 → vision_output.json + 근거 파일 참조 → 백엔드 → Agent
```

설치 비율은 ROI 내 `설치 / (설치 + 미설치)`이며 가림·대상 아님을 분모에서 제외한다. 가시성 부족 등 품질 조건을 만족하지 못하면 계산 불가로 처리한다. 이 수치는 실제 면적이나 매장 전체 공정률이 아니다.
카메라 이동·구도 변화 시 동일 ROI로 단순 비교하지 않고 대상과 비교 영역을 다시 확인한다.

반전·다중 배율 추론(TTA), 작은 ROI 확대, 가시성 인지 인과 보정(VCC)은 코드에 남아 있지만 **서비스 기본값에서는 끈다.** 아래 3장의 실험에서 기본 추론보다 나아지지 않았기 때문이다.

## 3. 실험 결과 요약 (2026-11, LOSO 규격 `loso-v1`)

현장 하나를 통째로 시험용으로 비우고 나머지로 학습하는 현장 단위 교차검증 결과다. 동결 DINOv2-B/14 위에서 디코더만 바꿨고, 시드 3개(Linear는 1개) 평균이다. 값은 학습에 쓰지 않은 현장의 날짜×벽 설치율 MAE(%p)이며 낮을수록 좋다.

| 디코더 | SITE_A | SITE_B | SITE_C | 평균 A·B·C | SITE_D (철거·재시공) | 벽 mIoU |
|---|---|---|---|---|---|---|
| **UPerNet** | 4.45 ± 0.17 | 4.10 ± 0.49 | 7.76 ± 0.35 | **5.44 ± 0.32** | 9.33 | 63.6% |
| Linear (하한선) | 5.45 | 5.12 | 7.02 | 5.86 | 15.08 | 58.1% |
| DPT | 6.23 ± 0.50 | 4.55 ± 0.34 | 7.33 ± 0.42 | 6.04 ± 0.29 | 15.29 | 61.7% |
| MLP | 7.68 ± 0.55 | 5.17 ± 0.12 | 6.70 ± 0.49 | 6.52 ± 0.28 | 10.55 | 57.8% |

- **디코더:** UPerNet이 MLP·DPT보다 유의하게 낮았다(짝지은 부트스트랩 B=10,000, 차이 1.08·0.60%p). Linear와의 차이는 유의하지 않았다(0.12%p, 95% 신뢰구간 [−0.46, 0.72], 공통 시드 0). 디코더 차이는 ROI가 사진의 1% 미만인 작은 벽에 몰려 있었고, SITE_C에서는 순위가 바뀌었다.
- **같은 현장 대비 간극:** 학습에 쓴 현장의 검증 세트 MAE는 1.5%p 안팎으로, 새 현장 오차의 약 1/4이다.
- **추론 기법:** 다중 배율은 작은 벽에서만 도움이 됐고(UPerNet 5.88 → 4.58%p) 전체 평균은 그대로였다. 작은 ROI 확대는 모든 디코더에서 오차를 키웠다.
- **시간축 보정(VCC):** 단순 인과 보정보다는 나았지만 기본 추론을 넘지 못했다(UPerNet 5.44 → 5.76%p). 모델이 과대 예측하는 경향(+3.4%p)이 있는데, 보정은 값을 올리기만 하기 때문이다. 철거 현장(SITE_D)의 재시작 규칙도 효과가 없었다.
- **확신도 기반 검수:** 확신도 상위 50%의 날짜×벽만 자동 보고하면 UPerNet 오차가 5.44 → 4.32%p로 줄었다. 그래서 서비스는 보정 대신 이 방식을 쓴다.
- **완료 판정:** 설치율 90%를 완료로 볼 때 F1 0.92, ±10%p 이내 80%.
- **시연:** 학습에 쓰지 않은 SITE_A 사진으로 하루 단위 설치율을 추정한 결과, 일별 오차 4.3%p였고 벽별 완료 판정이 공정표 비교로 이어졌다(W01 계획대로 완료, W02 계획보다 2 작업일 빠름).
- **수치 안정성:** DPT는 FP16 오버플로 때문에 디코더와 헤드를 FP32로 계산하도록 고친 뒤 12회를 다시 학습했다. 내용은 [PROTOCOL.md](../../src/vision/state_pipeline/vision_preprocessing/train/loso/PROTOCOL.md) 9장에 있다.

실험 규격·분할·지표·통계 방법은 실행 전에 고정했으며, 결과는 이 규격으로만 해석한다. 사진·라벨·가중치·결과 원본은 공개하지 않는다.

## 4. 다음 계획 (비전)

| 순서 | 할 일 | 상태 |
|---|---|---|
| 1 | 논문 제출(UCWIT 2026, 11/5 제출 · 11/27~28 발표) | 진행 중 |
| 2 | 큰 인코더(DINOv2 ViT-L/14 + registers, Apache-2.0) 시스템용 실험. SITE_A에서 4.53 → 3.28%p(유의한 개선). SITE_B·C·D 결과로 추론 비용(약 163 ms/장, 학습 5.0 GB) 대비 채택 여부 결정 | 진행 중 |
| 3 | 데이터 추가: 새 현장 전처리·검수, 철거·재시공 구간 라벨 보강 | 계획 |
| 4 | 대상 확장: 천장 데이터 보강, 바닥 마감 등 새 대상 추가 학습 | 계획 |
| 5 | 라벨링 보조 도구를 상업적 이용 제약이 없는 Apache-2.0 구성으로 바꾼 뒤 새 규격 버전으로 재학습. 이전 결과와 섞지 않는다 | 계획 |
| 6 | 과대 예측 편향 줄이기: 보정 대신 학습 데이터·손실 쪽에서 원인 분석 | 계획 |
| 7 | 통합: `vision_output.json` 계약 확정 → 백엔드 저장·조회 → ALOHA 화면의 사람 검수 → Agent 보고서 (E2E) | 계획 |

새 학습·추론 성능과 실제 서비스 연동 성공은 각각 실행 기록으로 검증한다. 코드 정리를 성능 검증 완료로 표현하지 않는다.

## 5. 코드와 실험 범위

- [학습·추론](../../src/vision/state_pipeline/vision_preprocessing/train/): `train_quick.py`의 기본 인코더와 디코더가 현재 모델이다. `infer_quick.py`는 체크포인트에 저장한 설정으로 모델을 복원한다.
- [LOSO 규격](../../src/vision/state_pipeline/vision_preprocessing/train/loso/PROTOCOL.md): 위 결과를 낸 연구 비교 규격·평가·수치 안정성 기록. 기존 규격과 결과의 의미를 바꾸지 않도록 그대로 보존하며, 바꿀 때는 새 버전을 만든다.
- [백엔드 문서](../public/README.md): 공개 문서와 SQL만 포함. API 실행 코드는 별도 관리되므로 이 저장소만으로 통합 서비스가 구동되지는 않는다.
- [웹 시연](../../prototype/public-demo/README.md): 가상 자료와 브라우저 저장을 쓰며 실제 추론·백엔드·Agent 연결은 별도 작업이다.
