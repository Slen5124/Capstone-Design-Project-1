# 현재 A안 비전 파이프라인

갱신일: 2026-10-11 · 팀 설명 기준 · 라벨 제작에 SAM3 채택

## 프로젝트 상태

A안(현장 사진 기반 글로벌 리테일 매장 공사관리 지원)으로 확정해 진행 중이다. 세 분할 모델의 성능 비교까지 프로젝트 범위에 포함한다. 논문 주제에 이 비교를 포함할지는 미정이다.

분석 대상 공종·구역, 상태 클래스 이름과 정의, 측정 기준·산식은 아직 정하지 않았다. 상태별 클래스를 분리해 표현할 계획이며, 분석 기준이 확정되기 전까지 특정 공종이나 공정률 수치를 확정된 요구사항으로 취급하지 않는다.

## 1. 라벨 제작용 모델

Grounding DINO + SAM 2.1 경로와 SAM3를 비교한 뒤, 팀은 **SAM3를 라벨 제작 도구로 선택**했다. SAM3가 만든 마스크·라벨 초안은 사람이 확인·수정하고 상태별 정답을 확정해 **GT(Ground Truth, 학습에 사용할 정답 데이터)**로 쓴다. 비교 조건·정량 평가·선택 이유의 세부 내용은 확인된 실험 기록이 준비되면 보완한다.

| 모델 | 선택 상태 | 주요 특징 | 인풋 | 아웃풋 |
| --- | --- | --- | --- | --- |
| Grounding DINO | SAM 2.1과 조합해 비교한 경로 | DETR 계열 오픈보캐뷸러리 객체 검출. 텍스트로 지정한 대상을 찾음 | RGB 사진 + 텍스트 프롬프트 | 후보 바운딩 박스 + 텍스트 대응 점수 |
| SAM 2.1 | DINO와 조합해 비교한 경로 | 프롬프트 기반 영역 분할. 점·박스가 지정한 대상의 윤곽을 분할 | RGB 사진 + DINO 박스 또는 사람이 준 점·박스 | 픽셀 마스크 + 마스크 품질 추정값 |
| SAM3 | 현재 GT 제작에 채택 | 텍스트·시각 예시 기반 개념 분할 | RGB 사진 + 텍스트 또는 시각 예시 | 대상 마스크·박스·점수 |

비교한 다른 경로는 Grounding DINO의 후보 박스를 SAM 2.1에 전달하는 방식이다. 현재 흐름은 아래와 같이 SAM3를 사용한다. 대상 영역의 초안을 생성한 뒤 상태 라벨도 사람이 검수한다. 상태 클래스의 명칭·기준은 아직 정하지 않았다.

```text
학습용 RGB 사진 + 텍스트·시각 예시
       ↓ 선택한 라벨 제작 도구 SAM3
후보 마스크·라벨 초안
       ↓ 사람이 영역·상태 검수·수정
학습 GT 확정
       ↓ 원본 RGB 사진 + 검수된 GT
ResNet-50 기반 DeepLabv3+·U-Net·Mask R-CNN 학습·비교
```

## 2. 대상·상태 인식용 모델

원본 사진과 SAM3 초안을 검수해 만든 GT로 다음 후보를 학습하고 성능을 비교한다. 비교 결과가 좋은 모델을 운영 모델로 선택하는 과정은 프로젝트 산출물이다. 실제 사진은 학습을 마친 선택 모델의 가중치를 사용해 이 단계에서 처리한다.

| 후보 모델 | 주요 특징 | 학습 인풋 | 추론 인풋 | 아웃풋 | 계획된 ResNet-50 구성 |
| --- | --- | --- | --- | --- | --- |
| DeepLabv3+ | 의미 분할. Atrous convolution·ASPP로 여러 범위의 문맥 활용 | RGB 사진 + 픽셀별 정답 마스크 | 새 RGB 사진 | 픽셀별 클래스 점수·마스크 | ResNet-50 백본 |
| U-Net | 의미 분할. 인코더–디코더 skip connection으로 위치·경계 정보 전달 | RGB 사진 + 픽셀별 정답 마스크 | 새 RGB 사진 | 픽셀별 클래스 점수·마스크 | ResNet-50 인코더 |
| Mask R-CNN | 객체 검출 + 인스턴스 분할 | RGB 사진 + 객체별 박스·클래스·마스크 | 새 RGB 사진 | 객체별 박스·클래스·점수·마스크 | ResNet-50 FPN 백본 |

DeepLabv3+와 U-Net은 이미지 픽셀을 클래스별로 나눈다. Mask R-CNN은 객체 인스턴스별로 나눈다. 따라서 비교 전에 서로 다른 출력을 공통 클래스 기준으로 맞추는 방법을 정한다. Mask R-CNN으로 한 대상 내부의 여러 상태를 표현하려면 상태별 인스턴스 정의나 추가 출력 구조가 필요하다.

비교에 사용하는 원본 사진·정답 기준·데이터 분할은 공통으로 고정한다. 픽셀별 GT와 객체별 박스·클래스·마스크처럼 모델마다 필요한 정답 형식은 해당 기준에 맞춰 변환·검수한다.

상태 클래스 체계와 출력 헤드 구성은 미정이다. 모델은 상태 마스크·클래스 결과를 출력하며 공정률을 직접 출력하지 않는다. ResNet-50을 포함한 학습 구성의 초기 가중치와 동결 여부는 실험 설정에 기록한다.

성능 비교를 프로젝트 범위에 포함하되, 비교 지표·합격 기준·논문 주제 여부는 추후 결정한다.

## 3. 전후 사진 매칭용 모델

두 시점의 사진에서 같은 위치의 대응 관계를 찾는다. 매칭 모델은 공종·벽 ID·시공 상태를 판정하지 않는다.

| 모델 | 주요 특징 | 입력 | 매칭 출력 |
| --- | --- | --- | --- |
| LoMa-L | 지역 특징 기반 매칭. 특징점과 주변 표현을 이용해 대응 위치 연결 | 과거 RGB 사진 + 현재 RGB 사진 | 대응하는 특징점 좌표 쌍 |
| RoMa v2 | 밀집 특징 기반 매칭. 이미지 전반의 대응 관계 추정·보정 | 과거 RGB 사진 + 현재 RGB 사진 | 밀집 대응 관계·대응점 및 overlap·불확실성 관련 정보 |

```text
과거 사진 + 현재 사진
       ↓ LoMa-L 또는 RoMa v2
대응 위치·점 추출
       ↓ 별도 기하 변환 및 정합 품질 검증
두 시점의 상태 마스크를 공통 좌표에 정렬
       ↓ 공통 관찰 영역에서 상태·변화 계산
자체 후처리 코드가 결과 JSON 생성
```

비교 전 같은 대상인지 확인하고, 대응점을 이용한 기하 변환·정합 검증을 별도로 수행한다. 정합이 검증된 공통 관찰 영역에서만 상태를 비교한다. 이 절차와 측정 기준이 확정되기 전까지 구체적인 변화량을 공정률로 부르지 않는다.

## 4. JSON과 Agent 연결

RoMa·LoMa의 출력은 매칭 정보다. JSON 파일은 매칭·분할 결과, 근거와 검증 상태를 프로젝트 후처리 코드가 모아 생성한다. 구체적 JSON 스키마는 라벨과 측정 기준을 결정한 후 고정한다.

```text
실제 현장 사진
       ↓ 학습을 마친 선택 모델로 추론
대상·상태 클래스 결과 + (필요 시) 검증된 사진 매칭 결과
       ↓ 자체 후처리·스키마 검증
비전 결과 JSON + 근거 파일 참조
       ↓
서버·백엔드가 결과 검증·저장·공정표 연결·조회
       ↓ 서버에 축적된 분석 결과 + 문서 근거
Agent 보고서 작성·질의응답
```

관측 결과와 전체 현장 공정률을 연결하는 산식은 아직 미정이다. 기준이 확정되기 전에는 모델이 계산하지 않은 공정률이나 지연 판단을 Agent가 임의로 만들지 않도록 한다.

## 역할 분담

| 팀원 | 고정 역할 |
| --- | --- |
| 이윤한 | 비전 팀 리드: 모델 학습·추론·학습 테스트 |
| 강태웅 | 비전 데이터 전처리 |
| 강원준 | Agent·RAG |
| 김병조 | 데이터베이스·백엔드 |

모델의 역할과 입출력은 팀에서 제공한 설명을 기준으로 정리했다. 실제 구현 라이브러리·체크포인트·출력 키는 실험 구성에서 확인하고 고정한다. 원본 멘토 미팅 PDF와 수행계획서 PDF는 저장소에 공개하지 않으며, 공개용 내용은 [기획 자료 요약](project-background.md)에 재서술했다.
