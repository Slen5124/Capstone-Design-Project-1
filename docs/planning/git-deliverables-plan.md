# Git에 올릴 산출물과 구현 우선순위

작성일: 2026-09-28 · 갱신일: 2026-10-11 · A안·SAM3 선택 반영 · 아래 이슈는 원격 등록 전 초안

## 1. 추천 방향

저장소의 대표 결과물은 **현장 사진의 관측 결과를 근거와 함께 조회하고, 공정 기준과 비교해 검증된 설명을 제공하는 작은 E2E 데모**로 잡는다. 후보 기술 이름을 많이 나열하기보다 결과 수치의 출처·계산식·검토 상태가 끝까지 보이도록 한다.

현재 A안은 확정 과제다. 공식 과제명은 **Development of an AI-Powered Construction Management Support System for Global Retail Stores**, 팀명은 **Team Aloha (알로)**다. 분석 대상·상태 클래스 정의·측정 기준은 미정이며 비전 개발은 다음 순서로 계획한다.

1. Grounding DINO + SAM 2.1과 비교해 선택한 SAM3로 마스크·라벨 초안을 만들고, 사람이 영역·상태를 검수·수정해 GT(학습 정답)를 확정한다. 라벨 도구의 세부 비교 조건·수치는 확인된 기록이 준비되면 추가한다.
2. 원본 사진과 검수한 GT로 ResNet-50을 백본 또는 인코더로 사용하는 DeepLabv3+·Mask R-CNN·U-Net을 학습하고 같은 평가 조건에서 성능을 비교한다. 비교와 운영 모델 선택까지 프로젝트 범위에 포함하며 논문 주제 포함 여부는 미정이다.
3. 선택 모델의 상태 분석 결과를 사용하고, LoMa-L 또는 RoMa v2로 전후 사진의 대응 위치를 찾는다. 동일 대상 여부와 별도 기하 정합·검증을 통과한 공통 영역을 비교한다.
4. 실제 사진은 학습을 마친 선택 모델로 처리한다. 자체 후처리 코드로 분석 결과·정의된 측정값·근거·판정 불가 사유를 JSON으로 생성해 서버로 전달한다. 전후 비교 결과는 필요 시 포함한다.
5. 서버·백엔드가 JSON을 검증·저장·조회하고 공정표에 연결하면, 에이전트가 서버의 분석 결과와 문서 근거를 바탕으로 보고서와 질의응답을 제공한다.

백엔드·에이전트는 실제 모델 결과를 기다리는 동안 합성 JSON으로 병행 개발한다. 첫 통합 예제는 단일 사진의 결과 수신·조회·템플릿 보고서로 구성하고, 실제 추론과 전후 사진 비교를 순차 연결한다. CLIP 증류와 VLM 라벨 검수는 별도 성능 개선 실험으로 둔다. 상세 역할은 [현재 비전 파이프라인](current-vision-pipeline.md)을 따른다.

현재 프로젝트는 사용자 확인에 따라 시공 상태·공정 분석으로 변경되었으며 루트 README에 반영했다. 아래 폴더는 **구현 시 사용할 제안 구조**이며, 제안된 코드와 API가 구현된 상태는 아니다.

원본 현장 사진·공정표 대신 직접 만든 합성 예제를 기본 데모에 사용한다. 저장소의 CONTRIBUTING.md는 원본 CCTV·개인 식별 데이터·기업 내부 자료의 공개 업로드를 금지한다. 외부 자료를 넣는 경우 공개 가능 여부와 사용 조건을 확인한다. 대형 모델 파일 대신 모델 식별자·버전·획득 절차를 기록한다.

기존 .gitignore는 CSV·XLSX 등을 제외하므로 최초 공개 예제는 JSON을 제안한다. 자료를 추가하려고 추적 제외 규칙 전체를 해제하지 않는다.

멘토 미팅 자료와 수행계획서 PDF 원본은 공개하지 않는다. [과제 변경 경위·기획 자료 요약](project-background.md)에 재서술한 과제명·선택 배경·시스템 흐름을 문서로 올린다. 두 원본의 파일명은 .gitignore에도 명시한다.

## 3. 가장 먼저 합의할 결과 계약

최종 스키마 이전의 **필드 설계 제안**이다. 확정된 API 명세가 아니다. 상태별 클래스를 분리하되 목록·정의는 추후 결정한다. 초기 계약은 클래스 결과와 근거를 전달하는 틀부터 준비하고, 구체적 측정값은 기준 확정 후 추가한다.

| 필드 묶음 | 예시 필드 | 규칙 제안 |
| --- | --- | --- |
| 버전·식별 | schema_version, analysis_id | 스키마 버전 명시, 중복 분석 ID 처리 규칙 고정 |
| 대상 | site_id, zone_id, task_id, image_id | 공정표 작업과 연결 가능한 안정된 ID 사용 |
| 시간 | captured_at, processed_at | 시간대가 있는 ISO 8601, 촬영과 처리 시각 구분 |
| 추론 조건 | model_version, roi_version, label_schema_version, output_type | 결과 재현에 필요한 버전과 의미 분할·인스턴스 분할 출력 구분 |
| 클래스 결과 | class_results, class_id, pixel_count, instance_count, mask_refs | 정의 버전과 함께 저장. 출력 단위에 맞는 필드만 사용하고 클래스명은 확정 후 추가 |
| 계산 결과 | metrics, metric_name, metric_value, unit, metric_version | 기준 미정이면 비워 두고 사유 기록. 단위·유효 범위·계산 불가 처리는 규칙 확정 후 검증 |
| 품질 | quality_status, quality_reasons | valid / needs_review / failed와 사유를 함께 저장 |
| 전후 비교 | reference_image_id, matching_model_version, registration_version, comparison_status, common_region_ref, change_metrics | 대응점과 별도 정합 검증·공통 영역을 추적하고, 비교 불가 시 사유 기록 |
| 근거 | evidence_refs | 원본·ROI·마스크·오버레이를 가리키는 식별자 |

촬영 결과와 공정 비교 결과는 분리하는 것을 제안한다. 계획표가 갱신되어도 원래 관측값은 유지하고, 비교 결과에는 schedule_version, as_of_date, comparison_rule_version을 붙여 다시 계산할 수 있게 한다. 실제 공정률 환산 규칙이 없으면 차이·지연 여부를 확정하지 않고 비교 불가 이유를 기록한다.

합성 예제는 최소한 다음 경우를 포함한다.

1. 정상 전달: 가상 클래스 결과·마스크 참조·모델 버전이 같은 내용으로 저장·조회됨
2. 측정 기준 미정: 클래스 결과는 전달하고 metrics는 비워 둔 채 미정 사유 기록
3. 입력 오류: 음수 개수·정의에 없는 class_id·알 수 없는 버전 → 명확한 오류 반환
4. 근거 부족: 결과 수치는 있지만 근거 이미지 또는 문서 인용 없음 → 확정 보고서 제한
5. 계획 매핑 없음: task_id에 대응하는 공정표 없음 → 관측값만 제공
6. 전후 비교 불가: 다른 대상 또는 정합 검증 실패 → 변화량을 비워 두고 사유 기록

예제의 클래스는 테스트용 가상 정의로 표시한다. 실제 분석 대상이나 측정 산식이 확정된 것처럼 수치를 채우지 않는다.

| T09 | 보고서 생성과 수치·날짜 검증 구현 | 강원준 + 김병조 | T04, T07, T08 | 수치 조작·잘못된 날짜·근거 누락 예제를 검토 대상으로 반환 |

| T11 | 증류·VLM 검수 등 성능 개선 실험 검토 | 이윤한, 라벨 검수는 강태웅 협업 | T05B, 핵심 기능 일정 확인 | 기준 대비 비교표, 비용·한계, 채택 여부 기록. 논문 주제는 별도 결정 |

첫 통합은 가상 클래스 계약으로 T02 → T03 → T04를 먼저 진행할 수 있다. 실제 측정 기능은 T01 결정 후 연결한다. 라벨 정의와 데이터가 확보되면 T05A → T05B는 백엔드 작업과 병행할 수 있다. T08도 문서가 있으면 병행하되 T09의 수치 판정은 정형 API 결과를 기준으로 한다.

## 6. 평가와 포트폴리오에서 보여줄 증거

- **측정 근거:** 초기에는 ROI → 클래스 마스크·근거 참조까지 보여준다. 측정 기준 확정 후에는 적용 산식·단위·계산 결과까지 연결한다.
- **재현 가능한 비교:** 같은 데이터 분할과 장비에서 모델별 상태 인식 성능·추론 비용을 비교한다. 출력 단위가 다른 모델의 공통 비교 기준을 기록하고, 측정 오차는 산식 확정 후 추가한다. 실험 전 숫자를 채우지 않는다.
- **실패 처리:** 전부 가린 사진, 잘못된 JSON, 누락된 공정표, 근거 없는 답변이 어떻게 처리되는지 보여준다.
- **에이전트 신뢰성:** 모델이 생성한 수치와 원본 결과가 다른 사례를 탐지하는 평가를 둔다. 작은 평가셋에서의 성공을 전체 정확도 보장으로 표현하지 않는다.
- **운영 흐름:** 분석 ID로 결과·버전·근거·검토 상태를 다시 찾는 예제를 제공한다.

루트 README에 변경된 과제 설명과 분석·기획 문서를 연결했다. 구현이 진행되면 구현된 범위, 빠른 시작, 합성 데모, 평가 결과, 알려진 한계의 링크를 추가한다. 지금 단계에서는 기술 스택 나열보다 **측정 규칙 문서 + JSON 계약 + 첫 통합 예제**가 가장 먼저 올릴 가치가 있다.
