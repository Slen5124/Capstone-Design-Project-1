# 20개 테이블 통합 적용 계획

사용자가 승인한 20개 합의안을 운영 DB와 Git에 반영한다. 기존 기본 자료는 제자리에서 보존하고 빈 확장 테이블을 공통 이력으로 통합한다.

1. 운영 전체 백업을 PostgreSQL 사용자 전용 디렉터리에 저장하고 별도 DB에 복원한다.
2. 005 SQL은 기존 기본 12개를 보존한다. 교체 대상의 업무 데이터가 비어 있는지 잠금 안에서 확인하고, 프로젝트·분석·보고서 등 workflow 자료는 공통 이력으로 이관한다. 예상하지 못한 데이터가 있으면 전체 변경을 취소한다.
3. 신규 통합 테이블과 필드, 현장 범위를 검사하는 외래 키를 구성한다. 기존 workflow 저장소 7개는 공통 이력을 읽고 쓰는 호환 뷰로 바꾼다. 기본 업무 테이블은 정확히 20개가 된다.
4. 복원 DB에서 건수·기존 파일 연결·현장 격리 제약과 workflow 뷰의 삽입·수정·조회·중복 거부를 검사한다. 기존 SQLAlchemy workflow 코드의 저장 방식을 함께 확인한다.
5. 운영 백엔드와 주간 처리 서비스를 잠시 멈추고 직전 백업 후 하나의 트랜잭션으로 적용한다. 실패하면 롤백하고 서비스를 재개한다. 적용 후 서비스 health와 기존 조회·프로젝트 조회를 확인한다.
6. 적용 결과로 문서·ERD·사용설명서를 갱신한다. 접속 정보·운영 데이터·백업은 Git에서 제외한다. 변경 파일과 커밋 예정 diff의 보안 검사를 모두 통과한 뒤 업로드한다.

DB 테이블 통합과 사용자 인증 연결은 별도 범위다. 기존 내부 서비스 계정의 접근을 유지한다. 사용자별 RLS·컬럼 제한은 인증된 사용자 컨텍스트와 신규 API 연결을 확인한 뒤 별도 적용한다.

2026년 11월 9일 운영 적용을 완료했다. 실제 public 테이블 20개·필드 186개·호환/조회 뷰 12개를 확인했다. 새 설치 SQL은 빈 검증 DB에서 시험했다. 운영 원본 자료와 설정은 트랜잭션 안의 내용 지문 비교를 통과했고, 서비스 재개와 인증된 조회를 확인했다.
