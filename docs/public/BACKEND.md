# 백엔드 기능과 DB 구조

## 1. 구성 요소

| 구성 요소 | 역할 |
|---|---|
| FastAPI | 요청·파일·분석 결과를 받고 조회 결과를 반환 |
| SQLAlchemy | PostgreSQL에 데이터 저장 및 조회 |
| PostgreSQL | 현장·장소·날짜·모델·공정표·파일 메타데이터 보관 |
| Lightsail 파일 저장소 | 사진·JSON·Markdown·PDF·ZIP·가중치 원본 보관 |
| 외부 GPU 환경 | 팀이 모델 학습·추론을 실행하고 결과 생성 |

## 2. 기능과 구현 상태

| 기능 | FastAPI | SQLAlchemy | 상태 |
|---|---|---|---|
| 사진·결과 저장 | 사진/결과 JSON/변화 JSON/MD 수신 | 파일 정보 및 일일 기록 저장 | 구현 |
| 공정표 관리 | 원본 PDF 수신, 버전·작업 조회 | 일정·단일 선후 관계 저장/조회 | 구현; 작업 입력은 별도 프로그램 |
| GT 관리 | ZIP/manifest 수신, 등록 요청 | 학습 데이터와 검수 상태 기록 | 등록 구현; 승인 검증 미완료 |
| 모델 관리 | 가중치/설정/클래스/성능 파일 수신 | 종류·버전·파일 관계 기록 | 구현 |
| 자료 조회 | 현장·장소·날짜 조건 수신, 결과 반환 | 해당 관측·파일·공정표 조회 | 구현 |
| Drive 연결 | 지정 파일 직접 다운로드 요청 처리 | 크기·경로·체크섬·전송 상태 기록 | 구현 |
| 에이전트 호출 | 요청 전달 및 응답 반환 예정 | 필요한 자료 조회·결과 저장 예정 | 미구현 |

모델 종류는 U-Net, Mask R-CNN, DeepLab V3이며 프로젝트에서 ResNet-50 기반 구성을 사용한다. 백엔드는 모델을 실행하지 않고 팀이 만든 결과와 가중치를 받는다.

## 3. 데이터 흐름

```text
사진 → 팀의 GPU 분석 → 결과 JSON·변화 JSON·MD
                                ↓
                            FastAPI 수신
                                ↓
                  실제 파일 보관 + SQLAlchemy 호출
                                ↓
                        PostgreSQL 메타데이터 저장
```

사진·JSON 등을 DB의 대용량 바이너리 값으로 넣는 대신 파일로 보관하고 상대 경로·크기·SHA-256을 기록한다. GT ZIP과 운영 일일 자료는 별도 폴더 및 테이블 관계로 관리한다.

## 4. 테이블

| 테이블 | 보관 내용 |
|---|---|
| sites | 현장과 현지 시간대 |
| locations | 현장별 고정 촬영 장소 |
| daily_records | 장소별 하루 사진·결과·변화·MD 및 직전 관측 연결 |
| files | 상대 경로·파일 종류·크기·체크섬·상태 |
| gt_datasets | GT ZIP·manifest·라벨 버전·검수 상태 |
| model_versions | 모델 종류·버전·가중치·설정·클래스·학습 정보 |
| schedules | 현장별 공정표 버전 |
| schedule_sources | 공정표 원본 PDF |
| schedule_tasks | 작업명·주차·기간·선행·후행 |
| schedule_task_locations | 작업과 촬영 장소 연결 |

```text
현장
 ├─ 촬영 장소 ─ 일일 기록 ─ 사진/결과/변화/MD 파일
 └─ 공정표 버전
     ├─ 원본 PDF
     └─ 작업 ─ 촬영 장소 연결

GT 데이터셋 ─ 모델 버전 ─ 일일 기록
                    └─ 가중치/설정/클래스/성능 파일
```

## 5. 운영 규칙

- 장소별 현지 날짜당 대표 관측 한 건을 보관한다.
- 관측 시간은 시간대를 포함하고 현장 날짜와 일치해야 한다.
- 이전 비교는 같은 장소의 직전 완료 관측을 대상으로 한다. 첫 관측을 변화0으로 꾸미지 않는다.
- 비교할 JSON의 모델 버전·클래스·스키마·단위를 검증한다. 단순 JSON 차이를 공정률 확정값으로 취급하지 않는다.
- 공정표 작업의 선행·후행은 각각 최대 한 개이며 양쪽 연결을 같은 트랜잭션에서 저장한다.
- 파일은 크기·종류·체크섬을 확인한 뒤 ready 상태로 등록한다. 실패·불완전한 파일을 성공으로 처리하지 않는다.
- API는 서버 내부 주소에만 바인딩하고 PostgreSQL을 인터넷에 공개하지 않는다. 외부 공개 시 인증·HTTPS를 별도로 구성한다.
- systemd 서비스가 SSH 종료 이후 실행을 유지한다. 인스턴스를 정지하면 서비스도 정지한다.

## 6. 확인 및 남은 작업

AWS에는 지정 ZIP이 압축 상태로 저장돼 있다. 전송 도구가 Google MD5·파일 크기를 확인하고 SHA-256을 등록했으며 지정 파일이 ready임을 확인했다. FastAPI DB 연결과 서비스 재시작 상태도 확인했다.

GPU 실전송, 에이전트 연동, 결과 자동 업로드, GT 내부 라벨/분할 누수 검증과 승인, 서버 밖 백업은 후속 작업이다. 전체 인스턴스 재부팅과 실제 대용량 장애 복구는 확인하지 않았다.

## 7. DB 스키마 파일

[PostgreSQL 초기 SQL](../../src/backend/sql/001_initial.sql)에 테이블10개, FK, 유일성 제약, 인덱스와 공정표 단일 선후 연결 검증 트리거를 포함했다. 접속 정보와 실제 현장/사진 데이터는 없다. 새 빈 DB 초기화용이며 기존 AWS DB에 재실행하지 않는다.
